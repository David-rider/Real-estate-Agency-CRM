## 3. 明天的工作清单

建议顺序：**A 先合并本地代码 → B 打版本标签 → C 设置 GitHub 仓库 → D 核对线上 → E 统一升级和提交**。

### A. 本地代码合并

> 本地项目文件夹：`D:\study\projects01\Real estate-Agency-CRM`（路径里有空格，在 PowerShell 里要加引号）。
> 在 VS Code 里打开这个文件夹，用「终端 → 新建终端」最方便。

**A1. 先看本地有没有没提交的改动**
```bash
git status
```
- 有改动 → 先备份：`git stash push -u -m "local work before sync"`，合并完再用 `git stash pop` 取回。
- 如果不确定哪些改动要保留，**先不要合并**，把 `git status` 的输出发给我，我帮你判断。

**A2. 拉取最新的 `main`**
```bash
git fetch origin
git checkout main
git pull origin main
git log --oneline -3          # 第一行应是 91c78bb Merge pull request #2 ...
```

**A3. 如果你本地还有自己开发的分支**
```bash
git checkout 你的分支
git merge main                # 有冲突时逐个文件解决 → git add <文件> → git commit
```
遇到冲突的文件，建议优先保留 `main` 里的版本，再把你本地的改动手动加回去。尤其注意这些文件（今天改动最多）：
`backend/prisma/schema.prisma`、`backend/src/server.ts`、`backend/src/routes/*`、`frontend/src/app/*`、`frontend/src/lib/i18n/extra.ts`。

**A4. 安装依赖并检查**
```bash

npm install
npx prisma generate
npx tsc --skipLibCheck --noEmit

cd ../frontend
npm install
npx tsc --noEmit -p .
```

**A5. 本地数据库同步迁移**（只影响本地数据库，不影响线上）
```bash

```
本地数据库如果是以前用 `db push` 建的，这条命令会自动处理基线。

**A6. 清理本地旧文件**（Windows 上可能残留）
- `backend/dist/`：已不再纳入 git，可以保留，也可以删除。

### C. GitHub 仓库设置（需要你登录 GitHub 操作）

仓库地址：https://github.com/David-rider/Real-estate-Agency-CRM → **Settings**。云端环境没有仓库设置的权限，所以只能你来点。
按重要程度排序，前 4 项建议明天一定做完。

**C1. 安全告警与自动修复**（Settings → Advanced Security，旧界面叫 Code security and analysis）
| 开关 | 建议 | 作用 |
|---|---|---|
| Dependency graph | 开启（公开仓库默认开启） | 识别依赖 |
| Dependabot alerts | **开启** | 依赖出现新漏洞时发邮件告警 |
| Dependabot security updates | **开启** | 自动提交修复漏洞的 PR |
| Secret scanning | **开启**（公开仓库免费） | 发现提交了密钥时告警 |
| Push protection | **开启** | 提交里带密钥时直接拦截推送 |
| Private vulnerability reporting | **开启** | 别人发现漏洞时可以私下报告给你，而不是公开发 Issue |
| Code scanning（CodeQL） | 可选，建议开启默认配置 | 自动扫描代码里的安全问题 |

**C2. 保护 `main` 分支**（Settings → Branches → Add branch protection rule 或 Rules → Rulesets）
- 分支名：`main`
- ✅ Require a pull request before merging（至少 0–1 个审批，一个人开发可以设为 0）
- ✅ Require status checks to pass（等 CI 建好之后再勾选；目前只有 Vercel 预览检查）
- ✅ Block force pushes、Restrict deletions
- ⚠️ 不要勾选 “Do not allow bypassing”，否则你自己也推不上去。
- 效果：以后所有改动都必须通过 PR 合并，不会被误推或误删。

**C3. 合并设置**（Settings → General → Pull Requests）
- ✅ Automatically delete head branches（合并后自动删除分支）
- Allow merge commits：保持开启（目前一直用这种方式）。

## 5. 今天遇到的环境限制（供参考）

- 云端环境推送版本标签时连接被中断，因此标签需要在本地打。
